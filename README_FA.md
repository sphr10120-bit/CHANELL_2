# ربات خبر پیکسل‌مدیا — نسخه Railway

این بسته کد قابل‌استقرار است، نه سرویس از قبل راه‌اندازی‌شده. هیچ توکنی داخل بسته نیست و هیچ پستی ارسال نشده است.

## امکانات
- بررسی چهار منبع هر پنج دقیقه با Railway Cron و خروج از برنامه پس از پایان هر اجرا.
- کشف RSS/Atom از صفحه اصلی و مسیرهای رایج، با استخراج لینک HTML به‌عنوان مسیر جایگزین.
- استخراج متن، تاریخ اصلی انتشار و تصویر با metadata و JSON-LD و HTML.
- خلاصه فارسی و تشخیص موضوع با API سازگار با OpenAI سرویس Coarena.
- مقایسه رویداد با حداکثر ۶۰ خبر اخیر در ۱۴ روز گذشته برای کاهش تکرار بین سایت‌ها.
- عنوان برجسته با 🟦، دقیقاً دو بند و پایان برجسته 🆔️ @pixelmediair.
- تصویر با کپشن؛ اگر تلگرام صریحاً تصویر را رد کند، متن تنها ارسال می‌شود.
- عدم انتشار خبرهای قبل از زمان راه‌اندازی، با ثبت اولین اسکن موفق هر سایت به‌عنوان خط مبنا.
- ذخیره سابقه، خلاصه، شناسه پیام و وضعیت ارسال در SQLite.
- توقف خودکار ارسال مجدد در وضعیت نامعلوم شبکه برای کاهش خطر پست تکراری.

## راه‌اندازی Railway
۱. ZIP را از حالت فشرده خارج کن. فایل‌های داخل پوشه پروژه را در ریشه یک مخزن خصوصی GitHub قرار بده؛ فایل ZIP را به‌تنهایی آپلود نکن. فایل‌های مخفی تنظیمات هم باید همراه پروژه باشند. کلیدها را داخل GitHub نگذار.
۲. در Railway یک پروژه از همان مخزن بساز. Dockerfile و railway.toml داخل پروژه هستند.
۳. یک Volume به همین سرویس متصل کن و Mount Path را دقیقاً /data بگذار. بدون Volume، سابقه با استقرار مجدد ممکن است از بین برود. یک replica و یک سرویس نویسنده داشته باش.
۴. در Variables مقادیر زیر را وارد کن:

TELEGRAM_BOT_TOKEN = توکن ربات تلگرام
COARENA_API_KEY = کلید API سرویس Coarena
COARENA_MODEL = شناسه مدل مجاز در حساب تو
COARENA_BASE_URL = https://coarena.ai/api/v1
TELEGRAM_CHANNEL = @pixelmediair
DB_PATH = /data/pixelmedia.sqlite3
MAX_ARTICLES_PER_RUN = 6
DRY_RUN = true

نام مدل عمداً از پیش انتخاب نشده است؛ فهرست مدل‌ها تضمین نمی‌کند کدام مدل برای حساب تو رایگان است. از پنل حساب، مدل مجاز و سهمیه آن را بررسی کن. برنامه هیچ درخواست افزایش اعتبار یا فعال‌سازی پلن پولی ارسال نمی‌کند، اما اگر مدل انتخابی هزینه‌دار باشد ممکن است از اعتبار موجود استفاده کند.

۵. ربات باید در کانال مدیر و دارای اجازه Post Messages باشد.
۶. در Settings بررسی کن Cron Schedule برابر */5 * * * *، دستور شروع python bot.py و Restart Policy برابر Never باشد. وب‌سرور، دامنه عمومی، پورت و healthcheck لازم نیست.
۷. اولین اجرای موفق هر منبع صرفاً خبرهای موجود را baseline می‌کند. در Logs باید شمار خبرهای کشف‌شده را ببینی. اگر منبعی شکست بخورد، اولین اجرای موفق بعدی آن منبع هم baseline خواهد بود؛ در این حالت ممکن است برخی خبرهای زمان اختلال عمداً ارسال نشوند تا خبر قدیمی منتشر نشود.
۸. پس از بررسی لاگ‌ها و خروجی آزمایشی، DRY_RUN را false کن و دوباره Deploy کن. این کار انتشار خودکار به کانال را فعال می‌کند. خبرهای جدیدِ جمع‌آوری‌شده در حالت آزمایشی ممکن است پس از فعال‌سازی ارسال شوند؛ هیچ ارسال دستی آزمایشی خودکار انجام نمی‌شود.
۹. مصرف Railway و Coarena را از پنل‌ها پیگیری کن. رایگان‌ماندن تضمین نیست و Volume هم جزئی از منابع مصرفی میزبان است.

## انتخاب مدل و تست محلی (Linux/macOS یا WSL)
Python 3.12 پیشنهاد می‌شود. قفل فایل به fcntl وابسته است و برای Windows خام طراحی نشده است.

python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m unittest discover -s tests -v
python bot.py --list-models

فایل .env.example فقط الگو است؛ برنامه آن را خودکار بارگذاری نمی‌کند. متغیرها را با export یا تنظیمات Railway وارد کن. برای تست محلی DB_PATH را مسیر قابل‌نوشتن مثل ./local-data/news.sqlite3 بگذار.

python bot.py --dry-run
python bot.py --status

--dry-run هیچ چیزی در تلگرام منتشر نمی‌کند، اما از API مدل استفاده می‌کند و داده‌های کشف‌شده و خط مبنا را در دیتابیس نگه می‌دارد. صرفاً تغییر DRY_RUN به true لزوماً تمام پردازش را بدون کلید تلگرام اجرا نمی‌کند؛ برای اجرای محلی بدون کلید تلگرام از آرگومان --dry-run استفاده کن.

## وضعیت‌ها و رفع اشکال
- baseline: مطلب موجود هنگام اولین اسکن موفق؛ ارسال نمی‌شود.
- old: تاریخ قبل از شروع؛ ارسال نمی‌شود.
- undated: تاریخ انتشار معتبر پیدا نشده؛ برای جلوگیری از خبر قدیمی ارسال نمی‌شود.
- filtered: مدل آن را خبر بازی با محتوای کافی تشخیص نداده است.
- duplicate: رویداد مشترک تشخیص داده شده است.
- pending/retry: منتظر پردازش؛ پس از پنج تلاش خودکار متوقف می‌شود، اما در دیتابیس می‌ماند.
- sending/uncertain: ممکن است پیام ارسال شده باشد. خودکار تکرار نمی‌شود. کانال و message_id و URL را بررسی کن؛ فقط پس از اطمینان از عدم ارسال، با تهیه نسخه پشتیبان دیتابیس وضعیت همان رکورد را به retry و attempts را به صفر برگردان. تغییر گروهی نده.
- sent: تلگرام ارسال را تأیید کرده است.

برای گرفتن خروجی وضعیت، python bot.py --status را در محیطی اجرا کن که Volume واقعاً متصل است. محیط‌های موقت CLI ممکن است به Volume سرویس دسترسی نداشته باشند.

خطای احراز هویت یا سهمیه Coarena: متغیرها، مجوز inference:write و پذیرش شرایط API و سهمیه مدل را در پنل بررسی کن. توکن‌ها را در لاگ یا اسکرین‌شات عمومی نشان نده.

## منابع و محدودیت‌های مهم
این نسخه زنده با توکن‌های واقعی یا HTML فعلی همه منابع آزمایش نشده است. رابط عمومی استخراج منابع در کد وجود دارد، اما در صورت تغییر ساختار سایت یا مسدودسازی دسترسی، به تنظیم adapter نیاز دارد. مسیر feed قطعی برای هر چهار سایت ادعا نشده است؛ برنامه آن را در زمان اجرا کشف می‌کند. اگر feed معتبر خاصی پیدا کردی، متغیر SOURCE_FEED_URL مربوط را تنظیم کن: MOONMEDIA_FEED_URL، GAMEFA_FEED_URL، ZOOMG_FEED_URL یا VIGIATO_FEED_URL.

robots.txt رعایت می‌شود و دورزدن محدودیت یا CAPTCHA انجام نمی‌شود. اجازه robots.txt به معنی مجوز بازنشر نیست. حق انتشار خلاصه و خصوصاً تصویر را باید بررسی کنی؛ تصویر خودکار لزوماً مجوز استفاده ندارد. حذف نام منبع مطابق درخواست توست و مجوز بازنشر ایجاد نمی‌کند. در صورت الزام منبع به ذکر نام/لینک یا مجوز، پیش از فعال‌سازی رعایتش کن.

تشخیص خبری‌بودن و تکرار معنایی وابسته به مدل است و خطاناپذیر نیست. پنجره مقایسه ۱۴ روز و ۶۰ رویداد است، نه تمام خبرهای تاریخ. لینک‌های قبلاً دیده‌شده دائماً در دیتابیس محفوظ‌اند. خبرهای بدون تاریخ معتبر برای حفظ شرط «فقط پس از شروع» منتشر نمی‌شوند. اختلال طولانی ممکن است باعث شود خبری از فهرست RSS خارج شود و هرگز کشف نشود.

تیتر حداکثر ۹۰ کاراکتر و دو جمله، هر بند حداکثر ۳۰۰ کاراکتر و بدون شکست خط داخلی است. تعداد خطوط دیداری به فونت و عرض صفحه بستگی دارد؛ دو/پنج خط در تمام دستگاه‌ها قابل تضمین نیست. متن کوتاه نگه داشته شده تا با محدودیت کپشن معمول تلگرام سازگار باشد. 🟦 ایموجی است، نه فایل استیکر تلگرام.

در ارسال تلگرام «دقیقاً یک بار» تضمین‌پذیر نیست: اگر پاسخ پس از دریافت پیام در شبکه قطع شود، وضعیت uncertain ثبت می‌شود و نیاز به بررسی دستی دارد. هدف این تصمیم جلوگیری از تکرار است؛ گاهی یک خبر ممکن است در این وضعیت ارسال‌نشده بماند.

هر اجرا حداکثر حدود ۴ دقیقه بودجه دارد و پردازش پیش از پایان بودجه متوقف می‌شود؛ درخواست در حال اجرا ممکن است کمی بیشتر طول بکشد. خبرهای مازاد در صف می‌مانند و سرعت انتشار به حجم خبر و سرعت API بستگی دارد. Railway دقت دقیقه‌ای را تضمین نمی‌کند و اجرای هم‌پوشان را رد می‌کند.
